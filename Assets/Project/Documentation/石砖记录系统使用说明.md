# 石砖记录系统使用说明

## 先理解这三个概念

1. **关卡解锁**：决定玩家能否进入某一关，由 `DataSystem.IsLevelUnlocked(levelId)` 判断。第一关默认解锁。
2. **石砖登记**：在 `RecordUI` 预制体的 `Record Window > Bricks` 中填写石砖的 `Id`、`Display Name` 和 `Sprite`。登记只告诉界面“这块砖长什么样”，不会让它自动出现在记录里。
3. **石砖获得**：调用 `DataSystem.UnlockBrick(id)` 后，记录界面才会显示对应条目。每块砖单独保存，同一关可以获得多块。

目前有一个明确的例外：`gengzhong`（耕种图）是**初始拥有**的石砖，所以新存档打开记录也应该看到它。第一关通关按钮的 `Reward Brick Ids` 当前包含 `gengzhong`；由于同一 ID 不会重复获得，通关时不会多出一条耕种图记录。其余石砖必须配置获得时机。

## 添加一块新石砖

1. 在 Project 窗口打开 `Assets/Project/Prefabs/RecordUI.prefab`。
2. 选中根节点 `RecordUI`，找到 Inspector 中的 `Record Window (Script) > Bricks`。
3. 增加一个元素，填写：
   - `Id`：唯一且固定的英文 ID，例如 `level1_secret`。保存后不要改名，否则旧存档找不到这块砖。
   - `Display Name`：记录条目上显示的中文名称。
   - `Sprite`：石砖图片。
   - `Detail Sprite`：详情页和放大查看用的高清图片，可单独指定。留空时沿用 `Sprite`，不会自动提升原图分辨率。
   - `Image Caption`：图片说明，区分游戏复原图、实物照片或拓片。
   - `Era`、`Excavation Site`、`Current Collection`：年代、出土地、现藏地。
   - `Interpretation`：图像解读，支持多段文字，界面自动换行并可滚动。
   - `Sources`：可追溯的资料来源，建议填写正式图录名称、页码、文物编号或博物馆公开链接。
4. 保存预制体。随后按下面任一种方式配置获得时机，使用**完全相同**的 ID。

`Bricks` 中可以连续登记多块属于同一关的砖，不需要把它们合并为一条记录。数组中的顺序就是记录界面的显示顺序。

## 在关卡完成时获得

项目的第一关完成按钮使用 `NextLevelButton`：

1. 打开 `Assets/Project/Prefabs/Level1.prefab`，找到挂有 `NextLevelButton` 的完成按钮。
2. 在 `Reward Brick Ids` 中增加元素，每块要奖励的砖填一个 ID。例如同时填写 `level1_secret` 和 `level1_finish`。
3. 原有按钮点击事件 `UnlockAndShowNextLevel()` 会解锁 `Next Level Id` 指定的下一关，并保存这里填写的所有石砖。

如果某个选关页面使用 `LevelUnlock.OnUnlockButtonClick()` 来解锁下一关，也可以在该组件的 `Reward Brick Ids` 中填写多个 ID。应在**实际执行解锁的组件**上配置奖励；不要只填在没有被调用的组件上。

### 示例：第一关通关后再解锁一块扬场图

可以直接配置，**不用添加 `BrickUnlockTrigger`，也不用修改代码**。以下以新石砖编号 `yangchang` 为例。

1. **先登记石砖**：打开 `Assets/Project/Prefabs/RecordUI.prefab`，选中根节点，在 `Record Window (Script) > Bricks` 中新增一项。填写 `Id = yangchang`、`Display Name = 扬场图`，并配好图片和详情资料。编号必须与下方奖励配置完全一致。
2. **找到第一关通关按钮**：双击打开 `Assets/Project/Prefabs/Level1.prefab`，在预制体层级中搜索 `btn_next` 并选中。
3. **增加通关奖励**：在 Inspector 中找到 `Next Level Button (Script)`，展开 `Reward Brick Ids`。当前只有 `Element 0 = gengzhong`，点击该数组下方的 **＋**，或者把右侧数量从 **1 改为 2**，将新增的 `Element 1` 填为 `yangchang`。新增元素可能复制原来的值，要确认已经改为新编号。

   ```text
   Reward Brick Ids
     Element 0：gengzhong
     Element 1：yangchang
   ```

4. **保留原有按钮配置**：`Next Level Id` 保持为 **2**；上方 `Button > On Click()` 中原有的 `NextLevelButton.UnlockAndShowNextLevel()` 事件不用修改，也不需要再添加一次。
5. **保存并测试**：保存预制体，运行第一关，完成拼图后查看完成面板：砖图水平排列，提示本关解锁数量。再回主菜单打开画像砖录，检查扬场图是否出现，点击后能否查看详情。退出并重新运行后，已获得的石砖仍应保留。

**发放时机**：完成修砖拼图时立即发放 `Reward Brick Ids` 并保存；旧任务通关面板在显示时发放。下一关按钮仍保留发放作为兜底，重复调用不会重复收藏。旧存档新增奖励需要再次完成拼图或触发通关按钮，不会只因为改了配置就自动发放。

工作流程为：登记砖画资料 → 完成拼图 → 读取 `Reward Brick Ids` → 调用 `DataSystem.UnlockBrick(id)` 保存获得状态 → 通关面板显示奖励 → 回主页打开画像砖录查看详情。

### 收集进度与通关收藏提示

`RecordUI` 顶部显示“砖画收集：已收集数量 / 总数量”。总数取 Bricks 中有效且不重复的 ID；已收集数量与实际可查看条目一致，包含初始拥有的耕种图。重新打开界面或清空存档时自动刷新，不会重复累计同一块砖。

通关面板按本关 `NextLevelButton > Reward Brick Ids` 的顺序横向展示砖图及名称，并提示“本关解锁了N个石像砖，快回主页的画像砖录瞧瞧吧！”。空项不计数，相同 ID 只显示一次；这里的 N 表示本关配置的奖励数量，重复通关仍展示本关奖励。图片多时可横向拖动查看。未配置奖励时显示暂无新增砖画提示。

奖励图片、名称直接引用 `RecordUI` 的 Bricks 资料，不需要重复录入。新增奖励 ID 必须先登记，否则无法显示对应砖图。共用奖励界面配置位于 `Assets/Project/Resources/BrickRewardView.prefab`，保留 Catalog 对 RecordUI 的引用即可。

## 在关卡过程中获得

适用于拾取物品、完成任务、对话结束等事件：

1. 给负责该事件的物体添加 `BrickUnlockTrigger` 组件。
2. 在组件的 `Brick Id` 填写已登记的 ID，例如 `level1_secret`。
3. 在该事件的 UnityEvent 中拖入这个物体，选择 `BrickUnlockTrigger > Unlock()`。

例如，用按钮测试时，在按钮的 `On Click()` 列表中指定上述 `Unlock()`。`BrickUnlockTrigger` **不会自动检测碰撞或任务完成**；必须由实际事件调用它。如果事件由代码控制，可在事件成功时直接调用：

```csharp
DataSystem.instance.UnlockBrick("level1_secret");
```

重复调用同一个 ID 不会生成重复存档，也不会让记录界面出现两个相同条目。

## 记录界面如何显示和保存

- `DataSystem` 跨场景存在，石砖状态由统一 JSON 存档系统保存；进入 `Index` 后再次打开记录仍会显示已获得的砖。
- `RecordWindow` 打开或重新启用时读取获得状态，为每块已获得的砖复制一个 `RecordItemTemplate`。未获得的砖不会显示。
- 如果记录界面**已经开着**，此时又获得新砖，需要关闭后重开，或者调用 `RecordWindow.Refresh()` 才会更新。
- `RecordItemTemplate` 应保持未激活，作为复制模板。`Index` 场景 `Content` 下手动添加的测试副本会一直显示，不受获得状态控制；正式使用动态记录时应移除或禁用这些测试副本。

## 查看文物详情与大图

点击任一已获得条目可打开文物详情：左侧显示砖画，右侧显示年代、出土地、现藏地、图像解读与资料来源。右侧可用鼠标滚轮、拖动或滚动条阅读长资料，切换条目后自动回到顶部。

点击左侧砖画进入大图。按钮或滚轮可在“适合画面”的 100% 到 400% 之间缩放；100% 指适合当前视口，不是源图像素一比一。放大后可拖动查看，点击“适合画面”恢复居中。触屏同时提供双指缩放及单指拖动，需在目标手机上验收多点触控。

“返回资料”只关闭大图，“返回砖录”关闭详情。Esc 每次返回一层。打开新图片会重置缩放，不继承上一幅的位置。

详情页位于 `RecordUI/BrickDetail`，大图位于其子节点 `BrickImageViewer`，均为已保存在预制体中的普通 UGUI 对象，可直接调整字体、颜色、布局和按钮。默认保持未激活。

当前五条资料使用项目已有的游戏图片，未补造高清原图或正式文物考据信息。年代只标注题材范围；具体原砖出土地、现藏地标注待考证，来源说明标注了当前依据与待核验内容。得到可靠资料后在 `Bricks` 中替换对应字段即可。

编辑器菜单 `Tools > 画像砖录 > 验证详情页` 可在临时预览中检查五条图片引用、详情开关、缩放边界、空字段回退与列表按钮事件，并将布局图和结果写入 `Artifacts/BrickRecord`。它不读写玩家存档，也不切换正在编辑的场景。

## 最短测试流程

1. 退出预制体编辑模式，打开 `Index` 场景，进入 Play 模式，在 **Game** 视图打开记录。新存档应该先看到“耕种图”。
2. 给一块新砖登记 ID、名称和图片，在一个测试按钮上按“关卡过程中获得”的步骤绑定 `Unlock()`。
3. 运行游戏点击测试按钮，关闭并重新打开记录，检查新条目是否出现。
4. 停止并重新进入 Play 模式，再打开记录，检查条目是否仍在。

若记录为空，先检查 `RecordUI > Bricks` 是否有对应 ID，再检查事件是否真的调用 `Unlock()`，以及两处 ID 是否逐字一致。预制体编辑模式使用临时画布，布局预览与 `Index` 场景不同；实际交互请在场景的 Game 视图测试。
