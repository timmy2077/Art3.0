# 统一存档系统

## 已接入范围

`SaveManager` 是唯一文件存储入口，`DataSystem` 保留原接口，因此选关、取名、音量和画像砖收藏的已有按钮引用不用重绑。`PlayerTaskManager` 的任务阶段和已完成目标也已接入同一文件。第一关原有 `FarmingPuzzle` 会据任务记录恢复牛栏、耕具和修复状态。

这是一个本地单存档槽系统，包含玩家名、关卡解锁、画像砖收藏、音量及开关、任务阶段与目标完成记录。**不包含角色精确位置、NPC 科普阅读状态、对话播放位置、云同步或多个存档槽。** “继续”表示进入原有关卡后恢复任务节点，不是任意时刻的场景快照。

## 自动初始化和保存

无需挂载新组件。现有 `DataSystem` 启动时访问 `SaveManager.Instance`，后者自动创建并跨场景保留；重复实例会销毁。

现有取名、解锁、任务完成、修改设置操作都会保存。游戏进入后台和正常退出时补存内存中尚未写入的修改。新接口 `Set*` 只修改内存，调用方完成一组修改后必须调用 `SaveNow()`，不要每帧写文件。

文件位于 `Application.persistentDataPath`：

| 文件 | 用途 |
| --- | --- |
| `game-save.json` | 正式 JSON 存档，版本 1 |
| `game-save.json.bak` | 前一次有效存档 |
| `game-save.json.tmp` | 保存时的临时文件，读取时不采用 |

编辑器中可用 `Debug.Log(SaveManager.Instance.SavePath)` 查看实际路径。开发环境和发布后的游戏路径可能不同。

写入先完成临时文件，再替换正式文件。正式存档损坏时尝试备份；两个文件都损坏，或发现更高版本存档时，禁止覆盖，控制台会报告原因。`SaveNow()` 返回成功与否，`LastError` 提供失败详情。发生错误时内存进度仍在，需解决磁盘问题后再次保存。文件替换依赖目标平台的文件系统支持；当前未实现 WebGL 浏览器文件同步，发布其他平台需实际验证。

## 旧存档迁移

首次启动且没有 JSON 存档时，按需读取旧 `PlayerPrefs` 数据。旧任务在以后进入对应关卡时继续导入，JSON 内的 `Save.LegacyImport` 记录该策略。新修改只写 JSON，不双写旧进度。原画像砖和音量迁移逻辑继续生效。

`PlayerPrefs` 仅保留旧数据读取及迁移标记 `ArtGame.JsonSaveInitializedV1`。清空新存档会关闭旧数据导入，避免旧进度复活；不会调用 `PlayerPrefs.DeleteAll()`，不影响其他插件的设置。不要单独删除 JSON 文件来实现“新游戏”，应使用下面的重置接口。

## 已有调用方式

```csharp
DataSystem.instance.SavePlayerName("玩家名");
DataSystem.instance.UnlockLevel(2);
DataSystem.instance.UnlockBrick("paochu");
bool unlocked = DataSystem.instance.IsLevelUnlocked(2);
// 任务仍由 PlayerTaskManager 接取、完成和恢复，不直接改 Quest 键。
PlayerTaskManager.Instance.CompleteTask(1);
```

新系统的简单标记：

```csharp
var save = SaveManager.Instance;
save.SetInt("Level2.Chest.Opened", 1);
if (!save.SaveNow()) Debug.LogWarning(save.LastError);
bool opened = save.GetInt("Level2.Chest.Opened", 0) == 1;
```

为每关、物品和任务分配稳定且唯一的 ID，不要用可修改的显示名字。相同键始终使用相同类型。任务 `questId` 必须唯一且在版本更新时保持不变。新增关卡的脚本应在初始化时读取标记，并主动恢复物体状态；存档管理器不会自动扫描场景。

## 全局关闭与重置

- `DataSystem.enablePersistence = false`：不再读取/写入该数据接口的持久化值；任务系统也服从此开关。它不是运行中清空按钮，已加载的内存进度仍然保留。任务组件自己的 `enablePersistence` 可以额外关闭任务存档。直接调用底层 `SaveManager` 不受这个游戏接口开关限制，测试时不要绕过接口。
- 全部清空：调用 `DataSystem.instance.ClearAllData()`，或继续使用记录面板原有“清空存档”按钮。会重置玩家名、进度和音频设置，同时重置当前任务管理器内存，并将重置结果写入正式文件与备份。
- 重置后应返回选关页并重新创建关卡。已生成的牛、耕具、对话窗口等场景物体不会全部自动重建，不应停留在旧关卡继续玩。
- `SaveManager.ResetOccurred` 可用于其他系统清理内存缓存，订阅后记得退订。`SaveManager.DeleteAll()` 是底层接口，游戏 UI 应使用 `DataSystem.ClearAllData()`，以同步其缓存。

主菜单设置页已接入：`新入画境` 调用 `IndexMainMenu.NewGame()`，弹出确认框后调用 `DataSystem.StartNewGame()`，重置关卡、任务与收藏，保留名字及音频设置，再进入 Start，重走开场流程；`归画继续` 调用 `ContinueGame()`。暂别画境仍退出游戏。关闭存档时不允许通过新游戏重置正式数据。

## 验收步骤

1. 原有存档下启动，检查玩家名、音量、解锁和任务节点迁移。
2. 完成第一关一个目标，退出并重新运行，确认任务及关卡物体恢复。
3. 解锁收藏和下一关，重新运行确认保留。
4. 修改音量，重新运行确认设置保留。
5. 退出游戏后备份存档，再人为损坏正式 JSON，启动确认恢复备份。
6. 通过记录面板清空，返回选关并重新运行，确认旧进度不会重新导入。
7. 关闭持久化进行任务调试，确认没有写入正式任务进度。

不能在游戏运行中直接编辑或删除文件来测试恢复：管理器会使用已加载的内存值。旧的第一关自动流程测试已经改为清理统一存档中的测试任务键。

## 维护与边界

存档是明文 JSON，不用于防作弊。格式版本变化时必须编写迁移，不要只增加版本号。备份提供的是上一次保存的状态，恢复时可能丢失最近一次修改。磁盘写入失败会报告错误，不保证断电或设备故障时零丢失。发布前需要在 Unity 2022.3 及目标设备执行以上验收。

已使用 Unity 2022.3 的实际引用程序集编译 SaveManager、DataSystem 和 PlayerTaskManager，编译通过。独立文件系统测试通过 12 项检查，覆盖旧值导入、跨重启保存、未访问任务延后迁移、备份恢复、重置及高版本保护；该测试使用 Unity API 替身，不等同于实际 Unity Play Mode 验证。尚未执行 Unity 内的关卡完整回归。

## 新游戏与继续游戏（主菜单）

- Index 场景的 `NewPaintingButton` 已从错误的 `QuitGame` 改绑到 `NewGame`。
- `Assets/file/UIMainview.prefab` 的 `ReturnToPaintingButton` 已从 `CloseWindows` 改绑到 `ContinueGame`。关闭设置页的其他按钮保持原行为。
- 新游戏：确认框提供取消与重新开始，按 Esc 也可取消。重置会覆盖当前进度和备份，名字与音量保留。它与记录面板的“清空全部存档”不同，后者会连名字和设置一起清空。
- 继续：`Game.ResumeScene` 记录目的地。进入第一关时记为 `Level1`，完成第一关时记为 `Select`。老存档没有该键时进入选关页，不清空既有进度。没有任何存档时也进入默认选关页。
- 恢复粒度是任务节点，不保存精确坐标、对话播放位置或拼图中尚未提交的操作。后续新增关卡需加入 ContinueGame 的允许列表，并在进入/完成时更新 `Game.ResumeScene`。
- 场景有效性在切换前检查，新游戏会在重置前检查 Start；文件写入失败会留在确认框并显示提示。新游戏开始清空后若磁盘中途故障，可能已部分写入，应检查控制台及备份。
- 若 Unity 中的 Index 场景尚有未保存改动，请核对按钮事件，避免以后保存场景时将磁盘上的新绑定覆盖为旧的 QuitGame。
