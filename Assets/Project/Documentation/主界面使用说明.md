# 主界面使用说明

打开 `Assets/Project/Scenes/Index.unity`，所有界面节点都位于 `Canvas/UIMainview`，可直接在编辑器调整。文字均使用普通 Unity UI Text，不使用 TMP。

## 按钮

- 入画闯关：保留原按钮事件，进入 Select。
- 画像砖录：保留 RecordWindowLauncher，打开现有 RecordUI。
- 左上头像和名字：保留 PlayerNameWindow，打开原取名窗口并保存名字。
- 人物志：打开故人列表，已相逢条目可点击查看人物身份、与主角的经历和已读对话回顾；待相逢条目不可点击。主界面上已相逢的人物图片也可直接打开档案。
- 旅途设定：按 SettingsDesign 参考图制作。乐声、声响分别使用独立音量滑条，拖动立即生效并自动保存；滑到最左侧静音。
- 归画继续：关闭设置；暂别画境：退出游戏，在编辑器里停止运行。

## 伙伴配置

选中 UIMainview，在 IndexMainMenu 的 Companions 中配置 Completed Level、Portrait、Caption 和 Display Name，分别指定主界面位置、图片组件和标签组件。人物名字和立绘优先使用下方人物档案 SO 中的配置；Display Name 仅作缺少档案时的回退。现在预留四位伙伴，立绘仍使用 baishen 占位；请在人物档案 SO 的 Portrait 中替换正式立绘。

当前项目通过“下一关已解锁”表示上一关完成，所以通关第 1 关并解锁第 2 关后，第一个伙伴出现。第一关默认解锁不会自动赠送伙伴。若以后加入独立通关数据，应将 IndexMainMenu.Refresh 中的判断改为该通关记录。当前四个位置并非无限扩展的自动布局。

## 人物档案 ScriptableObject

四份档案位于 `Assets/Project/Data/Companions/Companion1.asset` 至 `Companion4.asset`。第一份已填写耕民的身份和相助经历，并关联现有 `NPC1.asset`；其余三份保留占位内容，后续按角色设定补充。

选中资产后可编辑：

- `Display Name`：人物姓名。
- `Portrait`：人物立绘，同时用于档案和对应主菜单人物位置。
- `Completed Level`：通关哪一关后相逢，与主菜单对应位置的 Completed Level 保持一致。
- `Identity`：人物身份。
- `Shared Experience`：与主角的经历；在相逢后显示，建议只描述截至该关结束已发生的剧情。
- `Related Dialogues`：关联的 `DialogueData` SO，可填写多份，详情页从这些资产读取对话原文。

运行时从 `Resources/CompanionJournal.prefab` 创建新人物志，原 Index 场景中的旧 JournalWindow 保留但不再作为正式入口。也可在 IndexMainMenu 的 Journal Prefab 字段显式指定同类型预制体。列表与详情 UI 均保存在新预制体中，可在编辑器直接调整。

人物档案由 SO 渲染，不将玩家解锁状态写进 SO；相逢状态仍由 DataSystem 的关卡进度判定，待相逢按钮会禁用，直接调用打开方法也会检查状态。Esc 从详情返回列表，再按一次关闭人物志。

## 已读对话回顾

对话由 `DialogueManager` 正常播放时，一句文字自然打完，或玩家跳过打字使整句显示后，才记录该句已读。中途关闭且没有完整显示的句子不记录。未选择的科普或任务分支不会提前显示在回顾中。

对话原文来自关联的 DialogueData SO；已读标记保存在统一 JSON 存档中。每份对话 SO 的内部 historyId 自动采用资产 GUID，标记还区分对话分支、句子位置和文本内容。修改原文后，新文本不会误用旧的已读状态。复制 SO 后会使用新资产的 GUID，不能用复制资产冒充原对话记录。

旧存档没有历史已读标记，不会凭通关状态补造记录；需要重新交谈后才会在回顾中出现。重新开始或清空存档会清除已读进度。不要删除对话资产的 `.meta` 文件，否则 GUID 会改变，原有记录无法对应。

新建档案时，在 Project 右键选择 `Create > 尘封砖语 > 人物档案`，填写上述字段，再加入 `Resources/CompanionJournal.prefab` 根节点 CompanionJournal 的 Profiles 数组。新增主菜单人物位置还需要在 IndexMainMenu.Companions 中单独配置对应 UI，列表本身会根据 Profiles 自动生成。

编辑器菜单 `Tools > 人物志 > 验证人物档案` 可在临时预览中检查锁定状态、SO 内容渲染、未读分支过滤、对话完成回调、主菜单入口和宽屏布局；结果及预览图位于 `Artifacts/CompanionJournal`。验证不读写玩家存档。

## 入画序章

从 Start 开场流程进入 Index 时，自动显示石砖色全屏序章，以打字机效果分四节交代主角身份、触碰残砖入画、修复画像砖的原因，以及完成长卷寻找归途的目标。每次只显示一节，打完后停留 3 秒，清空文字并间隔 0.5 秒，再开始下一节。最后一节停留 5 秒，再淡出进入主界面。全程禁用菜单、键盘导航和鼠标交互，不支持跳过。

在 Project 中打开 `Assets/Project/Resources/IndexPrologue.prefab`，选中根节点的 `IndexPrologue` 组件即可修改 Story（文案）、Character Interval（逐字间隔）、Section Hold Seconds（每节停留）、Section Gap Seconds（节间间隔）、Final Hold Seconds（末尾停留）与 Fade Seconds（淡出时长）。Story 用空行分节，单个换行只在当前节内换行。背景颜色在“石砖底色”的 Image 中调整，字体和排版在“叙事区域”的 Text 中调整。

界面由 IndexMainMenu 在进入 Index 时自动创建，无需手动拖入场景。测试时请从 Start 运行并等待开场完成；直接运行 Index 或从关卡返回 Index 不播放。重新开始并再次经过 Start 会重新播放，不修改玩家存档。

## 美术与布局

以 1920 × 1080 横屏布局，CanvasScaler 同时匹配宽高。暂定标题为“砖上人间”，可直接修改 GameTitle 的 Text。

Art/UI/MainMenu/BaishenMenu.png 是 baishen.png 去除透明空白后的副本，原图未修改。InkHalo.png 是程序绘制的透明光晕。背景沿用现有纸张素材。

IndexMainMenuPreview.png 是根据场景坐标生成的布局预览，实际效果以 Unity Game 视图为准。Unity 中打开着旧场景时，应重新加载 Index；如有未保存的编辑，先另存备份，避免旧内容覆盖磁盘修改。

SettingsWindowPreview.png 是新版设置窗口的布局预览。设置面板位于 `UIMainview/ModalLayer/SettingsWindow/Panel`，比例为 540 × 628；所有标签都是普通 Text，两个控件为原生 Slider。背景、边框、按钮底图和圆形滑块位于 `Art/UI/Settings`。设置专用字体位于 `Fonts/SettingsKaiTi.ttf` 和 `Fonts/SettingsYaHei.ttf`。

首次读取旧版总音量存档时，会迁移到两个独立音量设置。新存档的音乐和音效初始值为 72% 和 82%，保留旧版音乐、音效开关状态。

## 调整滑条位置

选中 `MusicVolumeSlider` 或 `SoundVolumeSlider`，修改它们的 Pos Y，可将轨道、填充和圆形滑块一起移动。

每个滑条的结构为 Track、FillArea/Fill 和 HandleSlideArea/Handle。FillArea 高度为 5，HandleSlideArea 高度为 20；Fill 和 Handle 的锚点由 Slider 控制，保留它们的 Pos Y 为 0。单独调整填充的位置或厚度时修改 FillArea；单独调整圆形滑块的位置或高度时修改 HandleSlideArea。

## 主界面模块分层

UIMainview 下按绘制顺序分为 BackgroundLayer（背景装饰）、HeaderLayer（标题）、CharacterLayer（主角与伙伴）、StatusLayer（进度与页脚）、NavigationLayer（功能按钮）、PlayerLayer（头像与名字）、ModalLayer（取名、设置与人物志弹窗）。伙伴按 Companions/CompanionSlot1～4 分组，每组包含人物图片与说明文字。界面控制脚本仍挂在 UIMainview。

分组节点均为铺满父节点的 RectTransform，用于组织层级。弹窗在 ModalLayer 内排序，确保显示在主界面内容上方。

编辑器工具独立放在 `Assets/Project/Editor/Tools/UI/UIRectRoundingTool.cs`，运行时脚本留在 `Assets/Project/Scripts`。选中 UI 后，直接点击 Inspector 的 Rect Transform 组件底部“坐标与尺寸取整”，会将当前对象的位置及尺寸取整到整数。多选 UI 对象也可一次处理。受 Slider 或布局控制的 Rect Transform 会跳过。
