# 关卡配置指南

本文档说明《尘封砖语》如何新增/配置一个关卡。适用于 5 个画像砖关卡：农耕、庖厨宴饮、车马出行、四神灵瑞、墓主生活。

---

## 一、整体架构

| 层级 | 内容 | 是否每关单独做 |
|------|------|----------------|
| **通用基类** | `LevelBase`（修砖拼图、打字机提示、对话适配、存档、文字加载、世界标签） | ❌ 所有关卡继承，不用动 |
| **通用系统** | `LevelRuntimeBootstrap`、`DialogueManager`、`NPCInteraction`、`PlayerTaskManager`、`LevelTextLoader`、`NextLevelButton`、`LevelUnlock` | ❌ 共用 |
| **关卡脚本层** | `FarmingPuzzle`、`CookingPuzzle`… 各继承 `LevelBase`，只写本关玩法 | ✅ 每关一个 |
| **资源层** | `Level1~5.prefab` + `farming/paochu/yishi/sishen/muzhu.json` | ✅ 每关一套 |

> 核心原则：**`LevelBase` 封装所有通用逻辑，子类只实现本关特有的交互/提示/物体恢复。新关卡脚本天然不含牛代码。**

## 三、新增一关的完整步骤

以「庖厨宴饮」（第 2 关）为例。

### 步骤 1：写关卡脚本

新建 `CookingPuzzle.cs`，继承 `LevelBase`，实现抽象成员：

```csharp
public sealed class CookingPuzzle : LevelBase
{
    // 本关特有字段
    public Transform tableware, stove;   // 庖厨关的交互物体
    private Text npcName, itemName;
    private bool chefMet;

    // ===== 必须实现的抽象属性 =====
    protected override string LevelId => "paochu";
    protected override string ResumeSceneName => "Level2";
    protected override string BrickKey => "paochu";
    protected override int NextLevelIndex => 3;

    // ===== 文字加载（必须显式指定泛型类型） =====
    protected override void LoadTexts()
    {
        texts = LevelTextLoader.Load<CookingText>("paochu", () => (CookingText)BuildDefaultText());
    }

    protected override LevelTextBase BuildDefaultText()
    {
        return new CookingText
        {
            opening = new[] { new OpeningNotice { text = "...", seconds = 5f } },
            accepted = "...",
            puzzle = new PuzzleText { ... }
            // 本关特有字段...
        };
    }

    // ===== 存档恢复：本关物体状态 =====
    protected override void RestoreLevelProgress()
    {
        tableware.gameObject.SetActive(!tasks.IsTaskCompleted(1));
        stove.gameObject.SetActive(!tasks.IsTaskCompleted(2));
        chefMet = Accepted;
    }

    // ===== 每帧本关逻辑 =====
    protected override void UpdateLevel() { }

    // ===== 顶部提示文字 =====
    protected override string GetCurrentHint() { return "..."; }

    // ===== E 键交互 =====
    protected override bool TryInteract() { ... }

    // ===== 世界标签（NPC 头顶名等） =====
    protected override void PositionWorldLabels(Camera camera) { ... }

    // ===== 本关 UI =====
    protected override void BuildLevelUI(Transform canvas)
    {
        npcName = Label(canvas, "ChefName", "庖长", ...);
        itemName = Label(canvas, "ItemName", "食器", ...);
    }
}
```

### 步骤 2：写文字数据类

```csharp
[Serializable]
public class CookingText : LevelTextBase   // 继承基类，自带 opening/accepted/puzzle
{
    public HintsText hints;     // 本关特有
    public InteractText interact;
    // 按需加字段
}
```

### 步骤 3：复制预制体

1. 复制 `Level1.prefab` → `Level2.prefab`
2. 打开预制体，**删掉农耕关特有物体**（blackcow、whitecow、CowPen、耕具 tool 等）
3. 根节点移除 `FarmingPuzzle` 组件，添加 `CookingPuzzle`
4. 绑定通用字段（Player、Tasks、Storage、Font、Restored Brick、Next Level）和本关字段

### 步骤 4：建 JSON

`Assets/Project/Resources/LevelText/paochu.json`，字段和 `CookingText` 一一对应。

### 步骤 5：连接选关场景

`Select.unity` → 第 2 关面板的 `HideAndInstantiate` → `Prefab To Instantiate` 改为 `Level2.prefab`。

### 步骤 6：配置通关解锁

`Level2.prefab` 的 `NextLevelButton`：Next Level Id = 3，Reward Brick Ids = paochu。

### 步骤 7：测试

Play → 选关进入第 2 关 → 验证对话、任务、修砖、解锁第 3 关。

## 四、LevelBase 提供的通用能力（子类直接用，不用写）

| 能力 | 说明 |
|------|------|
| 修砖拼图 | 9 宫格交换、缺失一块、解锁/复原逻辑，只需配 `restoredBrick` Sprite |
| 打字机提示 | `Notice(message, seconds)` 自动逐字显示 |
| 对话 UI 适配 | 自动配置对话面板样式，NPC 头顶名跟随 |
| 存档 | 拼图进度、任务进度自动存取 |
| 开场文字 | 读 `texts.opening` 依次播放 |
| 接受任务提示 | 接受任务时自动显示 `texts.accepted` |

子类可调用的基类方法：`Notice()`、`Label()`、`MakeButton()`、`Place()`、`PositionWorldLabel()`、`SavePuzzleValue()`、`RefreshPieces()`。

## 五、文字 JSON 配置规范

### 通用字段（所有关卡都有，来自 LevelTextBase）

```json
{
    "opening": [
        { "text": "开场文字第一节", "seconds": 5.0 },
        { "text": "开场文字第二节", "seconds": 4.0 }
    ],
    "accepted": "已接到任务。",
    "puzzle": {
        "title": "...", "victoryTitle": "...", "storyWithPiece": "...",
        "hintLocked": "...", "hintUnlocked": "...", "puzzleButton": "拼图",
        "continueButton": "...", "returnButton": "...", "missingLabel": "缺失"
    }
}
```

### 本关特有字段

在 `CookingText` 里定义，JSON 里加对应 key。

### 改字流程

打开 `Assets/Project/Resources/LevelText/{关卡}.json` → 改字符串 → 保存 → Unity 自动重导 → Play 生效。

> 换行用 `\n`。

## 六、打字机速度

每个关卡脚本（继承 LevelBase）都有 Inspector 字段：

- **Notice Type Interval**：每个字的间隔秒数
  - `0.045` = 快（约 22 字/秒）
  - `0.08` = 中（约 12 字/秒）
  - `0.12` = 慢（约 8 字/秒）

位置：预制体根节点 → 关卡脚本组件 → 「提示文字打字机」分组。

---

## 七、对话系统（通用）

每个 NPC 挂 `NPCInteraction` + `DialogueData`。

- **核心 NPC**：`isCoreNPC = true`，首次对话有【任务线/科普线】选项
- **次要 NPC**：`isCoreNPC = false`，纯科普

对话内容在 `DialogueData` 资源（.asset）里编辑，不在 JSON。

---

## 八、任务系统（通用）

每关一个 `TaskDataStorage` 资源。任务完成调 `tasks.CompleteTask(id)`。

## 九、常见问题

**Q：新关卡脚本里会有牛的代码吗？**
A：不会。`LevelBase` 不含任何牛逻辑，赶牛代码只在 `FarmingPuzzle` 里。

**Q：JSON 改了没生效？**
A：确认 Unity 无编译错误；点击 JSON 触发重导；检查 key 名是否和 C# 字段完全一致。

**Q：`LoadTexts` 里为什么要写 `Load<CookingText>`？**
A：必须显式指定泛型类型，否则 `JsonUtility` 只反序列化基类 `LevelTextBase` 的字段，本关特有字段会丢失。

**Q：通关后下一关没解锁？**
A：检查 `NextLevelButton.nextLevelId` 和 `rewardBrickIds`。
